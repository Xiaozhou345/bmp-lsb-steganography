## 二、解析器放宽的两处校验

### 2.1 `biSizeImage`（DIB 头偏移 34）

旧规则：必须等于 `0` 或 `stride × 高`。
实测：教师提供的 `4X2.BMP`、`4X4.bmp`、`8X8.bmp`、`16X16.bmp`、`4X16.bmp` 统一写成 `宽 × 高 × 3`（按每像素 3 字节误算），例如 4×2 图存 24，正确值是 8。
新规则：接受 `0`、`stride × 高`、`宽 × 高 × 3` 三种取值；**像素区实际边界一律以 `bfOffBits + stride × 高` 为准**，不再信任该字段。

> 该字段在 BI_RGB 下本就不是必需字段，用错它不会影响像素读取正确性，只是写入器的习惯差异。因此放宽是安全的，而不是"为通过而放松"。

### 2.2 `bfSize`（文件头偏移 2）

旧规则：必须与文件实际长度严格相等。
实测：`256灰度/test6.bmp`（66616 vs 66614）、`test7.bmp`（263224 vs 263222）尾部多 2 字节。
新规则：要求 `bfOffBits + 像素区大小 ≤ bfSize ≤ 文件长度`；多出的尾随字节原样保留，不参与嵌入也不参与提取。

新增两个只读属性供报告引用：

| 属性 | 含义 |
| --- | --- |
| `bmp.pixel_end` | 像素区最后一个字节之后的位置 = `bfOffBits + stride × 高` |
| `bmp.trailing_bytes` | 文件尾部多余字节数 = 文件长度 − `pixel_end` |

## 三、冻结的调用（B、C 只许用这些）

```python
BMP.open(path)              # 解析 + 校验，失败抛 BMPError
bmp.info()                  # 宽、高、位深、类型、容量、像素偏移、行距、尾随字节、行序
bmp.capacity                # 可嵌入字节数 = 样本数 // 8
bmp.embed(payload) -> BMP   # 返回新对象，不修改 self；超容量抛 BMPError
bmp.extract(length) -> bytes
analyze(original, carrier)  # 修改样本数/比例、最大绝对误差、MSE、PSNR
```

约定：

1. `embed` 返回**新对象**，原对象字节不变——B、C 想同时保留原图与载体时直接各取一个对象。
2. 实验模块**不得**自己算像素偏移、行距、调色板索引。需要逐样本遍历一律用 `bmp.positions()` + `bmp.value(pos)`，否则灰度图会改错（改的是调色板索引而非灰度值）。
3. `analyze` 要求两图尺寸、方向、位深、调色板一致，剪裁实验前后尺寸会变，需在**剪裁前**先对同尺寸图做 PSNR，或自行按重叠区计算。
4. 任何实验模块都**不得**写入 `bmp_lsb.py`。需要新能力就新建文件，扩展点已留好（见第四节）。

## 四、新增模块（均不改 `bmp_lsb.py`）

### 4.1 `length_header.py` — 图内长度头

报告第 26 页要求回答"如何在嵌入信息的图片中存储嵌入的信息的长度"。原方案只靠同目录 `.bmp.lsb.json`，长度并没有进图片。本模块给出可辩护的设计：

- 容量 ≥ 5 字节时：前 32 个样本 LSB 存**大端 uint32 消息字节数**，其后接正文；
- 容量 ≤ 4 字节时（4×2 为 1 字节、4×4 为 2 字节）：装不下 4 字节头，自动退回 `BMP.embed` 满容量路径 + 外部给定长度，作业第 27 页用例因此不受影响。

| 调用 | 作用 |
| --- | --- |
| `embed_with_length(source, payload) -> BMP` | 嵌入并把字节数写进图内 |
| `extract_with_length(carrier) -> bytes` | 读头部长度后自动提取，无需外部给定 |
| `header_capacity(capacity) -> int` | 带头后可嵌入的正文上限 = `capacity - 4` |
| `needs_external_length(capacity) -> bool` | 容量 < 5 时返回 True |

代价与取舍（写进报告"关键问题"）：长度头固定吃掉 4 字节容量；4×2 那类极小图必须牺牲"图内可自解释"，这是容量与自描述性的直接冲突，无法两全。

### 4.2 `tools/bmp_probe.py` — 素材探测

只读前 54 字节，独立于 `bmp_lsb`。用途：

- `find_fixtures_root()` 自动定位素材目录（教师压缩包解开后多套了一层同名文件夹）；
- 逐张打印 `宽度/高度/位深/bfSize 差/biSizeImage/合规/容量`，解析器拒绝某张图时能立刻看出原因；
- `python tools/bmp_probe.py --fail-only` 只看异常项。

### 4.3 `tools/verify_fixtures.py` — 任务 0 回归

一次性产出三份证据：全量 34 张解析结果、第 27 页三个用例的真实素材结果、`test6/test7` 尾随字节保留情况。结果写入 `docs/素材核查.md`。
