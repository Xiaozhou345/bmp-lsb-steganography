# 作业要求与算法说明

## 要求对应

| 作业要求 | 实现 |
| --- | --- |
| 语言不限；不可使用现有图片处理函数库或工具包 | 标准库 `struct` 和字节操作手工解析、修改 BMP |
| 同时识别 256 灰度图和 24 位真彩图 | 读取位深，验证 BI_RGB；8 位图验证完整灰度调色板 |
| 不超过 512×512，宽度为 4 的倍数 | 读取宽高后逐项校验，支持正负高度 |
| 打开并显示图片 | 手工转换为 RGB 像素显示数据，Tkinter 负责显示 |
| 计算最大嵌入长度 | 灰度 `floor(W×H/8)` 字节；真彩 `floor(3×W×H/8)` 字节 |
| 输入信息并控制长度 | 按 UTF-8 实时计数字节，嵌入前强制校验 |
| 嵌入并保存 BMP | 每个灰度值或 B/G/R 分量替换一个 LSB，保留文件其他部分 |
| 打开载体并提取 | 无需原图，按指定字节数提取并解码 UTF-8 |
| 4×2 灰度图嵌入并提取 `?` | 1 字节容量，测试验证完整位序与提取结果 |
| 4×4 灰度图嵌入并提取 `?S` | 2 字节容量，测试验证完整位序与提取结果 |
| 4×4 灰度图处理 `AbCd` | 4 字节超出容量，拒绝嵌入 |
| 结果分析 | 修改样本数及比例、最大误差、MSE、PSNR |

核查来源包括原 DOCX 的全部正文和 15 张内嵌 PNG，其中参考界面和小图验收用例位于图片内。原文提到的“可供选用的图片”文件夹未随文档提供；本项目的四幅示例图为手工生成的替代测试图。

## 位序与长度

4×2 灰度图有 8 个可用 LSB，恰好容纳 `?` 的一个字节。为了保留全部容量，`BMP.embed` 不写入额外的长度头或终止符。GUI 保存时生成配套 `.bmp.lsb.json` 文件，记录消息字节数及 BMP 摘要，重新打开时验证并自动读取长度；记录中不包含消息明文。缺少有效记录的旧载体仍需手填长度；命令行仍显式传入长度。这是实现选择，原文未规定长度存储协议。

报告第 26 页要求回答“如何在嵌入信息的图片中存储嵌入的信息的长度”，因此另提供 `length_header.py`：容量 ≥ 5 字节时，前 32 个样本 LSB 写入大端 uint32 消息字节数，其后接正文，提取端无需外部给定长度；容量 ≤ 4 字节的小图（4×2、4×4）装不下 4 字节头，仍走满容量路径并由外部保存长度。代价是长度头固定占用 4 字节容量，详见 [接口约定](接口约定.md)。

每个消息字节按最高位到最低位嵌入。像素按文件中的存储顺序遍历；24 位图的分量顺序为 B、G、R。正高度 BMP 先处理底行，负高度 BMP 先处理顶行。提取使用相同顺序。

最大 512×512 灰度图容量为 32768 字节，真彩图容量为 98304 字节。行填充、调色板、文件头、像素前间隙和尾随数据不参与嵌入。

## BMP 支持范围

支持未压缩 BI_RGB、8 位 256 灰度图或 24 位真彩图，Windows DIB 头大小支持 40、52、56、108 和 124 字节。拒绝非灰度索引图、压缩 BMP、32 位图及不完整文件。

两处校验按教师提供的素材放宽，理由见 [接口约定](接口约定.md)：`biSizeImage` 接受 `0`、`stride × 高`、`宽 × 高 × 3`（教师小图统一误写为后者），像素区边界一律由 `bfOffBits + stride × 高` 决定；`bfSize` 允许比文件长度少若干尾随字节（最多实测 2 字节），尾随字节原样保留、不参与嵌入。

8 位 BMP 像素存储调色板索引。程序要求调色板完整包含 0～255 灰度值；先把索引映射为灰度，替换灰度最低位，再映射回索引。逆序或乱序的完整灰度调色板同样可处理，实际灰度误差不会超过 1。

## 质量指标

每个灰度值或颜色分量为一个样本：

```text
MSE = Σ(原样本值 − 载体样本值)² / 样本数
PSNR = 10 × log10(255² / MSE)
```

只替换 LSB，单个样本变化只能为 0、+1 或 −1，因此最大绝对误差不超过 1，MSE 不超过 1。MSE 为零时 PSNR 为无穷大；界面显示 `∞`，JSON 中使用 `null`。

近似独立均匀的消息位通常使参与嵌入的样本约一半发生改变，实际结果由原图和消息决定。实测值见 [实验结果](实验结果.md)。

LSB 隐写本身不提供加密、认证或从裸像素自动检测长度的能力；配套文件的摘要仅用于匹配图片，不是身份认证。错误长度可能导致乱码；未嵌入信息的图也可被解释为字节。载体经过重采样或格式转换可能丢失消息。
